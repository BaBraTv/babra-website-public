# BaBra WhatsApp chatbot setup

## Implementation

Endpoint: `/api/whatsapp/webhook` (GET verification, POST signed inbound events).
The initial bot offers a bilingual RW/EN menu, product enquiries, delivery enquiries,
human handoff details, and structured quote requests. It is a rules-based assistant,
not an AI model. Unsupported media prompts customers to send text or contact staff.

Quotes are stored in the existing Order table with `QUOTE_REQUESTED`, zero amounts,
and product/quantity/delivery details. Staff must confirm stock, pricing and delivery
before requesting payment. Inbound enquiries and the reply are saved in the existing
ContactMessage table and remain `IN_REVIEW` after automated replies so staff can
follow up. No schema migration, payment collection or stock changes are introduced.

The API verifies raw HMAC-SHA256 signatures before processing, filters by the configured
business phone ID, skips events older than 23 hours, bounds payload size, and serializes
concurrent deliveries using PostgreSQL transaction locks. A stable Meta-message-derived
receipt/order reference prevents duplicate orders. Failed sends return 503 for Meta
retry; an ambiguous external send followed by a database/network failure can result
in a duplicate reply, but not a duplicate order. Future reliable-queue work should
separate webhook acknowledgement and delivery for high-volume traffic.

## Production configuration

Configure only on the actual Vercel project serving www.babra.store. Never put secrets
in source code, screenshots, chat, NEXT_PUBLIC variables or public files.

- `WHATSAPP_VERIFY_TOKEN`: a new random value generated by the owner (at least 32 random bytes).
- `WHATSAPP_APP_SECRET`: App Settings > Basic > App Secret for BaBra Customer Assistant.
- `WHATSAPP_ACCESS_TOKEN`: a system-user token for the app and BaBra WABA, with required
  WhatsApp messaging/management permissions. Temporary dashboard tokens expire.
- `WHATSAPP_PHONE_NUMBER_ID`: `1270116849527700` as shown in the owner's dashboard.
- `WHATSAPP_GRAPH_VERSION`: a supported version selected from the app dashboard.
- Existing `DATABASE_URL` and TLS configuration must work; existing Order and ContactMessage
  tables must already be deployed. No automatic migrations are required for this change.

Redeploy after setting the variables. Confirm the public endpoint is deployed before
pasting `https://www.babra.store/api/whatsapp/webhook` into Meta's Callback URL field.
Use the identical verify token in Meta. Subscribe to the `messages` webhook field and
connect/subscribe the app to the existing BaBra WhatsApp Business Account. Complete
any Meta publishing/business verification requirements shown in the dashboard; it
currently says unpublished apps receive dashboard test webhooks only. A phone-number
registration checkmark alone does not prove end-to-end chatbot operation.

Verify GET responds with the plain challenge for the correct token and 403 otherwise.
Send a real inbound message from a separate phone after publishing. Verify delivery,
admin inbox visibility, quote creation, human follow-up and a repeated webhook event
without a second order. Do not claim activation until these checks succeed.

## Customer order format

```
ORDER
Name: Customer name
Product: For Her
Quantity: 2
Location: Country, city, delivery address
```

Supported products: For Her, For Him, For Kids; quantity 1–1000.
Mixed-product orders can be placed as separate requests or handled by staff.
No payment credentials or medical details should be requested.

## Validation

- `node --experimental-strip-types --test tests/whatsapp.test.ts`
- `pnpm exec vitest run tests/whatsapp-route.test.ts`
- `pnpm exec tsc --noEmit`
- `pnpm exec next build`

Route tests mock storage and Meta; they do not verify production DB locks, credentials,
Meta subscription/publishing or actual message delivery.
